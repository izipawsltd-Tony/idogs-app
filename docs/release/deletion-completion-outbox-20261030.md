## Actual capture barrier

Capture requires recent verified Auth for the scoped UID, a verified synthetic example.invalid email and precise end-user createdAt/identity matching the acknowledged intake's original authHash. No caller supplies a recipient, completion boolean or identity hash. The acknowledged intake, immutable source request marker/commitment and actual independent acceptance event must match. Missing/unacknowledged intake or a changed identity cannot capture.

Before any durable recipient receipt is published, a source transaction reads the request, processing lock and deterministic completion_capture_<nonce> mutation lease. A new lease requires an accepted request and no processing lock. It creates an active lease bound to the exact intake hash/UID/nonce/request hash. The existing worker actually queries these active mutation leases and holds before destructive work. A worker installing its processing lock first prevents capture; a worker arriving after the capture lease may lock but must hold.

The module rechecks precise Auth identity while this barrier is active, then transactionally creates one immutable private recipient intent in the separate local database. A new private receipt requires the original active capture lease without a receiptHash. A closed lease with missing independent capture history cannot reconstruct a replacement receipt from current Auth/source data. The document retains the synthetic address because a hash alone cannot support future delivery. Public results omit the address and Auth facts. Readback verifies the exact immutable capture receipt, then another identity check and source transaction close only the matching capture lease with its receipt hash. Unknown commit, missing receipt or changed identity never finally-close or time out the barrier. Restart with the same verified identity can recover an actual committed capture and close its exact lease; it cannot create a different recipient intent.

## Post-Auth evidence binding

bindCompletion never sends. Missing capture or independent completion history returns held. It requires the exact independent accepted/completed chain, unchanged acknowledged intake, source request binding, completed request/job/lock/receipt, matching revision/fingerprint/completedAt/retained-category commitment and closed capture lease containing the exact capture receipt. Actual Auth absence is checked independently; an enabled or disabled restored identity holds. Source and independent evidence are reread before and after the durable binding transaction, with a final Auth absence check. Errors other than an actual auth/user-not-found are not treated as absence.

The only terminal record state is completion_bound_no_send. This binds the recipient intent to observed completion evidence; it grants no dispatch permission. Restart repeats all current checks, even for that saved state. Tampered state/recipient/scope/revision, missing source, changed completion evidence or malformed chain rejects. A restored identity after a prior binding makes a subsequent call held. A concurrent restore can occur after any last read, so a historical saved binding is never a continuously current Auth assertion or a delivery-ready certificate.

There is no sender, queue dispatcher, provider adapter, message simulation, delivered flag, delivery-ready flag, cleanup scheduler or recipient expiration protocol. This minimal scoped test retains synthetic private recipient data only in the local named database; real recipient retention/access controls, encryption, secure transport, message policy, operational reconciliation, deduplicated provider acknowledgements and cross-service authority remain unimplemented.
