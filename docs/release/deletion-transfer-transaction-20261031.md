# Transfer transaction lock rechecks — 31 October 2026

The prototype ingress wrapper reads account deletion locks before invoking a route. That pre-handler lease alone does not prevent a deletion lock appearing before the route's ownership transaction. Actual transfer and claim handlers previously did not re-read those locks in their write transactions.

A new assertPrototypeAccountLocksTx is a no-op outside prototype-emulator. Inside that mode it revalidates the existing demo/Auth/Firestore/Storage runtime guard and bounded valid account scope before reading every account lock through the caller's transaction. Any lock, including malformed/completed tombstones, blocks. No Production adapter or configuration is enabled.

transfer-dog rechecks its verified source actor after reading current dog ownership inside the snapshot/transfer transaction. The pending buyer email is not treated as a destination UID. claim-transferred-dogs rechecks its verified recipient and source owners from the exact transferred-dog query snapshots in the ownership-changing transaction. Explicit malformed currentOwnerId does not fall back to tenantId. Prototype discovery is bounded to201 with overflow held; ordinary deployment retains the original query and response behavior. Transaction query/dog reads are the current version proof, not stale request data. Original breeder tenantId, quota eligibility, incoming restricted status and privacy snapshots remain intact.

Four actual SDK cases are prepared: source and destination locks installed after the outer ingress lease but before the real claim transaction must leave the dog/version unchanged; actual transfer must reject the same late source lock without creating a privacy snapshot; a no-lock claim with the existing Free two-dog cap still claims as restricted while preserving original breeder and restriction reason. Tests invoke actual route exports and actual Auth/Firestore emulators. A scoped transaction-method hook inserts only the synthetic lock after the first real lease transaction and is restored in finally. No Auth/provider calls are mocked. These extend the existing isolated sequential core suite, not a new cloud resource or local emulator server.
